# 实施计划文档

## 阶段 0：项目定义与运行基线

### 目标
- 明确 MVP 功能边界与运行规范。
- 保证任何人按文档可在本地启动并访问 Swagger。
- 规范环境变量与数据库迁移流程。

### 产出物
- 中文 README（项目说明、启动指引）。
- `.env.example`（环境变量模板）。
- 本计划文档（阶段 0 说明）。

### 可执行步骤
1) 补全 README：包含技术栈、环境要求、安装、迁移、启动、Swagger 地址。
2) 补充 `.env.example`：提供最小可运行配置。
3) 明确数据库迁移流程：生成与应用迁移的命令。
4) 统一接口与数据约定说明：金额精度、ID 类型、时间格式。

### 验收标准
- 新人按 README 能成功启动服务并访问 `/docs`。
- `.env.example` 可直接复制为 `.env` 并启动。
- 迁移命令在文档中清晰可执行。

### 里程碑
- 文档完善完成并通过自检。
- 环境变量与迁移流程确认无遗漏。

### 风险与对策
- 风险：环境变量缺失导致启动失败。
  - 对策：在 `.env.example` 中提供所有必需项并标注说明。
- 风险：迁移命令误用导致数据库不一致。
  - 对策：README 中明确生成与应用的使用场景。

### 目标

### 产出物

3) 明确开发与发布流程（生成、应用、回放）。

### 验收标准
- 迁移流程可复现且有文档约束。

## 阶段 2：认证与安全基础

### 目标
- 统一鉴权方式，确保核心业务接口需要登录。
- 处理 nonce 过期与复用，降低安全风险。

### 产出物
- 认证清理策略（过期/已用 nonce 清理）。
- Bills 接口补充鉴权。

### 可执行步骤
1) 在登录相关逻辑中清理过期/已用 nonce。
2) 所有业务接口统一使用 JWT 鉴权 guard。
3) 更新文档说明鉴权要求。

### 验收标准
- 过期/已用 nonce 不可复用且被清理。
- Bills 相关接口必须携带有效 JWT。

## 阶段 3：Agent 模块完善

### 目标
- Agent 列表支持分页与筛选，便于前端展示与运营管理。

### 产出物
- Agent 列表接口新增分页与筛选参数。
- 对应服务层实现分页与筛选逻辑。
- 字段校验规则增强（URL、价格格式、长度）。

### 可执行步骤
1) 列表接口增加 `page`、`pageSize`、`status` 参数。
2) 服务层按条件拼接查询并分页。
3) 更新接口文档说明分页与筛选规则。

### 验收标准
- `GET /agents` 可按 `status` 筛选。
- 分页参数生效且非法参数会被拒绝。

## 阶段 4：Job & 结算闭环加强

### 目标
- 增强提交结果与确认结算的幂等性与状态校验。

### 产出物
- Job 提交结果与确认结算的幂等处理。
- 状态校验更明确的错误提示。

### 可执行步骤
1) 提交结果时校验状态，仅允许 open/running。
2) 提交结果直接完成结算（跳过 pending_review）。
3) confirm 接口保留为兼容路径，仅返回当前 job。

### 验收标准
- 重复提交结果不会造成重复更新。
- confirm 接口不再触发结算，仅返回当前状态。

## 阶段 5：Wallet & Withdrawals 落地

### 目标
- 提现流程落地，余额与账本一致。
- 提现列表可查询当前用户记录。

### 产出物
- 提现创建接口真实逻辑（扣款 + 记录）。
- 提现列表接口真实查询。

### 可执行步骤
1) 校验提现金额与余额，事务内完成扣款与记录写入。
2) 写入提现记录（requested）与账本流水（withdraw）。
3) 提现列表仅返回当前用户，按时间倒序。

### 验收标准
- 余额不足时无法发起提现。
- 成功提现会写入 withdrawals 与 ledgers。

## 阶段 6：Bills 模块落地

### 目标
- 账单列表与详情返回真实数据，仅允许当前用户查看。

### 产出物
- 账单列表与详情接口实现真实查询。

### 可执行步骤
1) 账单列表按用户过滤并按时间倒序。
2) 账单详情仅允许查看自己的账单。
3) 文档更新鉴权与权限说明。

### 验收标准
- `GET /bills` 仅返回当前用户账单。
- `GET /bills/:id` 非 owner 无法访问。

## 阶段 7：链上事件同步

### 目标
- 后台轮询链上事件并同步提现状态。

### 产出物
- 链上事件轮询模块（无需外部推送）。
- 幂等写入 `chain_events`，更新 `withdrawals.status`。

### 可执行步骤
1) 读取链上配置（RPC、合约地址、起始区块）。
2) 轮询 `WithdrawConfirmed`/`WithdrawFailed` 事件。
3) 幂等写入 `chain_events`，更新提现状态。

### 验收标准
- 重复事件不会重复更新。
- 提现状态可随链上事件变更。
